# Plan Before Code

## Use this skill when
- Starting a new feature.
- Refactoring existing architecture.
- Approaching a task with ambiguous requirements.

## Do not use this skill when
- Fixing a one-line typo or extremely trivial bug.

## Process
1. **Understand**: Read the relevant existing code and user requirements thoroughly.
2. **Assume**: Explicitly state any assumptions you are making about the system or the user's intent.
3. **Clarify**: If an assumption is critical and ambiguous, pause and ask the user for clarification before proceeding.
4. **Breakdown**: Divide the work into small, verifiable steps.
5. **Execute**: Only begin modifying code after the plan is clear.

## Checklist
- [ ] Code context is understood.
- [ ] Assumptions are stated.
- [ ] Clarifications are requested if needed.
- [ ] Task is broken down into small steps.
